# MVP Scope Guardian

Use this skill to keep LIMA Office OS grounded in the first viable small-business deployment.

## Mission

Protect the Phase 0 and MVP boundary. The target is one small business, one Supervisor Server, 1-8 Arc worker mini PCs, optional 1-4 supervisor-side helper agents, Guardian-gated actions, and future LIMA IT tie-in.

## Scope Rules

- Prefer docs, contracts, and scaffolding before runtime implementation.
- Avoid enterprise features, multi-tenant platforms, broad SaaS assumptions, and generic marketplace features.
- Block marketing, pricing, financial projections, TAM, or sales copy unless explicitly requested.
- Keep connector work to readiness, risk, and contract posture until live wiring is approved.
- Keep automation draft-first and approval-gated.
- Treat production readiness claims as out of scope.

## Review Checklist

- Does this help the first small-business deployment?
- Is the feature needed before Guardian, worker, approval, evidence, and threat model contracts exist?
- Does it imply live connectors, external writes, hidden background work, or production operations?
- Can the same goal be handled as a doc, contract, or open question?
- Does wording drift into sales claims or financial projections?

## Output Standard

Call out scope creep plainly. Recommend the smallest Phase 0 artifact that moves the repo forward.
